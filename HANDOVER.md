# Shelf Check NZ: handover for Claude Code

Written 2026-10-15 (updated at packaging). Read this first, then `README.md`.

## What this is

A price-comparison site for NZ supermarkets. The user builds a grocery list and the site shows the cheapest way to buy it (one store, best two stores, cheapest across all), including a per-stop cost and per-100g prices.

- Repo: `ramdinsramdins-AI/Grocery` (public). Branch `main`.
- Live site: https://ramdinsramdins-ai.github.io/Grocery/ (GitHub Pages, branch `main`, folder `/docs`).
- The user is not a developer. They upload files through the GitHub web UI (Add file > Upload files, or the edit URL `https://github.com/ramdinsramdins-AI/Grocery/edit/main/<path>`). Give exact click-by-click steps for anything they do by hand. If you have git access, push directly and say what you changed in plain words.

## Architecture

```
scraper.py            Python scraper (requests). Writes docs/data/*.json
config.json           stores, categories, pacing (category_aliases is supported by the scraper but unused now)
ingredients.json      rules mapping recipe ingredients to supermarket products (see Recipes below)
collect-woolworths.js browser snippet that collects Woolworths from the user's own browser -> woolworths.json
woolworths-button.html  the same snippet as a bookmarks-bar button; rebuild with python make_woolworths_button.py
upload-woolworths.ps1   on the user's PC: every 10 min sends a new woolworths*.json from Downloads to GitHub, recycles old ones
install-woolworths-uploader.ps1  switches that Windows task on (or off with -Remove)
woolworths.json       repo root (not docs), pushed by the uploader or uploaded by hand. Used if < 7 days old
test_scraper.py       offline tests. Run: python test_scraper.py   (must print "all checks passed")
test_ingredients.py   170 product-name cases for the ingredient rules. Run: python test_ingredients.py
test_recipes.js       tests the JS pack-size calculator. Run: node test_recipes.js
.github/workflows/scrape.yml   cron 0 17,23,5 * * * UTC (6am/12pm/6pm NZ), workflow_dispatch, commits data
docs/index.html       static site, single file, no build step
docs/recipes.html     recipe page: choose recipes, get a combined shopping list with cheapest packs
docs/data/recipes.json            57 original recipes (hand authored): 27 general, 10 each Chinese, Japanese, Thai
docs/data/ingredient_products.json  generated by the scraper; shipped file is SAMPLE data (generated_at "sample")
docs/photos/          recipe photos go here (none yet)
docs/data/latest.json every product from the last run
docs/data/history.jsonl  one line per price change only
docs/data/compare.json   groups seen at 2+ stores, plus generated_at, stores_scraped_this_run, store_times
```

`generated_at == "sample"` marks the shipped sample data. `write_outputs` drops it on the first real run.

Unit prices are normalised to `100g`, `100ml` or `ea`. Cross-store matching uses `match_key` (brand + name words minus stopwords, plural-stripped, size words removed, plus normalised size), then a guarded fuzzy pass; see "Cross-store matching" below.

### Scraper behaviour you should preserve

- Polite: 2 to 4 s between requests, honest `User-Agent` (`ShelfCheckBot/0.1 (...)` with `SCRAPER_CONTACT` secret, sanitised for stray newlines). Stops on HTTP 403/429 (`Blocked`) and does not work around it. Retries timeouts and connection drops up to 3 times with backoff.
- Exit code 2 = at least one store failed but others worked. Exit 1 = nothing scraped. The workflow's Scrape step is `continue-on-error`, so exit 2 shows a green tick with an annotation. That is expected.
- A failed store keeps its previous rows, so one failure does not wipe its data.
- The workflow commit step copies fresh data to `/tmp`, resets to `origin/main`, then copies it back and commits. This avoids rebase conflicts on the data files when runs overlap. Do not replace it with a plain pull/rebase.

## Foodstuffs 1,000-result cap: fixed 2026-10-15 (not yet seen in a full run)

Checked live with the user's permission, 9 requests from their home connection (`--probe newworld --category Pantry`, `--probe newworld --category "Pantry > Spices, Seasoning & Coatings"`, `--probe paknsave --category Pantry`):
- The response has `totalHits`, `totalPages`, `hitsPerPage` and `algoliaSearchResult.facets`. A big category answers `totalHits: 1000, totalPages: 20`; the real size is not given anywhere (the `onPromotion` facet is keyed by store id, not a total).
- Asking for the `category1NI` facet gives every sub-category with its count (New World Pantry: 37 names, largest "Chips, Nuts & Snacks" 651). The filter `category0NI:"Pantry" AND category1NI:"Spices, Seasoning & Coatings"` works: `totalHits: 253`, and "Mild Curry Powder" is on its first page. PAK'nSAVE answers the same way.
- Products sit in several category trees (`categoryTrees` on each product), so the facet list also holds names from other trees ("Lunchbox Snacks", "Pams", "Game Day Hosting", "$5 Weeks 2"). Querying them only returns duplicates, which are dropped.

What `scrape_foodstuffs` does now: if page 0 of a category says `totalHits >= 1000`, it throws that page away and queues `"<category> > <sub>"` for every `category1NI` facet value (and `category2NI` one level further if a sub-category is also capped; below that it logs "cannot be split further" and keeps the 1,000). Records keep the top-level name as `category`, so the site and the recipe rules see no change. It also stops at `totalPages` instead of asking for an empty page. `--probe` accepts `--category "A > B"` and saves the category tree to `raw/<store>-categories.json`. Test: `test_scraper.py` runs the split on `fixtures/foodstuffs_split.json` (trimmed real responses).

Cost: New World Pantry goes from 21 requests to about 125 (all 37 facet values, roughly 6 more minutes at 2 to 4 s each), and the other capped categories grow the same way, so expect each Actions run to take noticeably longer. Possible saving later: only query the sub-categories that the category tree lists under that parent (New World Pantry has 16), about 20% fewer requests, at the risk of missing a product whose tree is unusual.

To check after the next run: the Actions log should show "search stops at 1000 results, splitting into N sub-categories" lines, the Pantry counts in `latest.json` should go well above 980, and `python scraper.py --ingredient-report` should find curry powder and garam masala at New World and PAK'nSAVE.

## Cross-store matching: Woolworths 18% to 26% (2026-10-15)

Measured offline on the real `docs/data/latest.json` (2026-10-14 runs, Woolworths file of 2026-10-12) with `python scraper.py --match-report`:

| | before | after |
|---|---|---|
| Woolworths matched | 1,983 of 10,640 (18.6%) | 2,790 (26.2%) |
| New World | 5,810 of 8,790 (66.1%) | 5,995 (68.2%) |
| PAK'nSAVE | 5,656 of 7,628 (74.1%) | 5,780 (75.8%) |
| groups | 6,171 (1,135 fuzzy) | 6,483 (1,936 fuzzy) |

816 new Woolworths links; 9 old links dropped, 7 of which were wrong (Carefree regular vs super tampons, Nurofen plain vs Cold & Flu, Dole pieces vs slices, Monster Ultra Vice vs Ultra Violet, Nivea Men vs women's roll-on). Two random samples of 30 new links checked by eye: 26/30 right (2 wrong, both then fixed by the SPF and drink-volume rules below; 2 unsure), then 29/30 right.

What `group_records()` does now, on top of exact `match_key` grouping (all in the cross-store matching section of `scraper.py`):
- **Brand prefix.** When one brand key is the other plus whole extra words ("mccain pub style" vs "McCain", "jed's" vs "Jed's Coffee Co."), the extra words count as name words; `BRAND_NOISE` (co, company, food, ...) is dropped from them. Brand keys are built from stemmed words without a leading "the" (`_brand_words`). The brand's words are also removed from the name, which handles Woolworths repeating the brand in every name.
- **Accents and joined words.** `_PLAIN` folds é, è, ’ and similar ("nescafé" = "Nescafe"); `_split_compounds` treats "supersoft"/"super soft", "kickstart"/"kick start", "spf30"/"spf 30" as the same words. `match_key` is unchanged on purpose (group keys stay stable).
- **Default words.** "original"/"classic" are no longer variant words but `DEFAULT_WORDS`: missing on one side is fine only when that side has no other words of its own ("Sweet Chilli Sauce" = "Original Sweet Chilli Sauce", but "Doritos Original" is not "Doritos Salsa").
- **Flavour on both sides.** `FLAVOUR_WORDS` block a match only when each name has a flavour the other lacks (raspberry vs watermelon). Tried as plain variant words first: that lost 186 mostly-correct links ("Arepa The Brain" vs "... blackcurrant"), so do not move them into `VARIANT_WORDS`.
- **SPF counts as a number** (day cream vs SPF30 day cream).
- **Multipacks** (`_size_keys`, `_alt_ok`): Woolworths "10pack" may meet Foodstuffs "10 x 100ml"; a weight in a Woolworths multipack name ("oxo beef stock cubes 71g", size "12pack") may be the whole pack or one item ("24g", "3pack" = "3 x 24g"); a volume in the name is always one item ("330ml", "8pack" = "8 x 330ml", never a single can). An alternative size only meets the other product's main size, and is only used when each product is the other's clear best match at that store (a "6pack" with no can size never picks between 6 x 250ml and 6 x 330ml).
- **Loose produce** (`_loose`): fruit and veg with no pack size (Woolworths "fresh fruit/vegetable/herb" names, Foodstuffs Fruit & Vegetables sized "kg"/"ea") match by name within per-kg or each, brand ignored, `PRODUCE_NOISE` words dropped, clear-best rule as above. 45 Woolworths produce lines now match (bananas, lemons, carrots, onions, apples by variety, broccoli...).
- Fuzzy pairs are now merged best-first across all blocks, which fixed a few old wrong groups (New World Mediterranean tonic was grouped with PAK'nSAVE Elderflower tonic).

Tests: `test_scraper.py` has 13 new must-match pairs taken from real names (all fail on the old code) and 10 must-not-match cases. The accent fix made Woolworths "chopped tomatoes in purée" count as tomato paste; `ingredients.json` tomato-paste now excludes "chopped" (plus a test case), and recipe picks on real data are identical to before.

Known wrong or doubtful matches left (all low-frequency, roughly 1 in 30 of the new fuzzy links):
- Made-up flavour names no word list knows: The Collective Splitz "bickies'n'cream" vs "Churro".
- Descriptor swaps at the 0.5 threshold: Nivea "Hydrating" vs "Caring" day cream, Banana Boat "smartmist" spray vs lotion. Raising the threshold to 0.6 when both names have their own extra words would fix these but lose about 150 mostly-correct links ("tub" vs "simply", "herbal tea" vs "tea bags"); not done.
- "fresh" is in `NOISE`, so Nivea "Invisible" vs "Invisible Fresh" can match.
- A Woolworths single 1.5 L bottle can meet Foodstuffs "6 x 250ml" cans (same 1,500 ml total). Adding "can"/"bottle" as variant words would lose 19 correct links for 1 fix; not done.

Where the rest are: of the 7,850 Woolworths products still unmatched, 1,241 are Woolworths' own brands (woolworths, macro, essentials) and 1,545 are brands New World / PAK'nSAVE do not stock, so they cannot match. Most of the other 5,064 have no same-brand product of the same pack size at Foodstuffs (different sizes, or not stocked). The Foodstuffs 1,000-result cap fix above should add products and raise this further after the next run. Ideas not done: a parent-brand suffix rule ("so good" vs "Sanitarium So Good", only about 10 products), "ies" plural stemming (berries/berry; `_stem` is shared with the recipe rules, so check `test_ingredients.py`), barcodes if a store ever exposes them.

## Recipes (new)

User request: about 100 recipes with photo, name, method and full ingredient list; the customer picks one or more and the site generates the whole grocery list. The hard part they raised: two recipes need 200 g and 500 g of chicken breast but stores sell 500 g and 1 kg packs.

How it works:
- `docs/data/recipes.json`: recipes with ingredients `{item, qty, unit}`. `item` is an id in `ingredients.json`. Units: g, ml, ea, tsp, tbsp, cup, pinch, plus per-ingredient ones in `units` (each, clove, slice, can).
- `ingredients.json`: per ingredient `base` (g, ml or ea), `include` (list of word groups: a product needs one word from every group), `exclude` words, `units`, `pantry`, `perishable`.
- `scraper.py` `build_ingredient_products()` (called from `write_outputs`, failures are caught so price data is never lost) finds matching products per store, works out pack size, drops price outliers (likely wrong matches), and keeps up to 6 cheapest-per-size packs per store (plus a loose by-weight price when sold per kg). Output: `docs/data/ingredient_products.json`.
- `docs/recipes.html` sums needs per ingredient across chosen recipes (scaled by servings), then `cover()` does a small dynamic programme per store to find the cheapest combination of packs that covers the amount (ties go to less waste), shows leftovers, a perishable warning and other recipes that could use them. Store plans (one store, best two, all) reuse the same logic as `index.html`. Pantry items (oil, flour, spices...) default to "already have" and the user can tick any ingredient. State is in localStorage `shelfcheck-recipes`.
- Not yet done: nutrition/allergens, unit conversions are rough averages (onion 150 g etc.), recipe quantities were written by Claude and not cooked or checked by a chef.

## Things that went wrong before (do not repeat)

- `git add` on a file that does not exist aborts the workflow: use `git add -A docs/data`.
- A trailing newline in the `SCRAPER_CONTACT` secret caused `InvalidHeader`. The code now sanitises it.
- Woolworths from GitHub Actions: `ReadTimeout`. Do not retry harder; use the uploaded file.
- Chrome blocks pasting into the DevTools console. Tell the user to use DevTools > Sources > Snippets instead.
- Test fixtures need identical product names (or a case like those in the matching block of `test_scraper.py`) to produce a match group.
- A matching rule that looks right on a few examples can still lose hundreds of correct links (flavour words as variant words: -186). Measure lost links on the real `latest.json` before keeping a rule.
- The Claude sandbox cannot reach the supermarket sites or `raw.githubusercontent.com`, so live behaviour can only be checked from the user's logs or from a real machine.
